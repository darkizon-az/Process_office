# Process Office Feedback

Работающий full-stack MVP для сбора, администрирования и анализа обратной связи о работе процессного офиса.

## Развёрнутое приложение

- Опрос: <https://process-office-feedback.onrender.com/s/feedback-2026>
- Вход администратора: <https://process-office-feedback.onrender.com/login>
- Проверка состояния: <https://process-office-feedback.onrender.com/api/health>
- Хостинг: Render, бесплатный Web Service
- База данных: Neon PostgreSQL
- Исходный код: приватный GitHub-репозиторий `darkizon-az/Process_office`

На бесплатном тарифе Render сервис останавливается после периода бездействия. Первый запрос после паузы может выполняться около 50 секунд, но адрес остаётся постоянным и не зависит от локального компьютера или туннеля.

## Возможности

### Опрос

- многошаговое заполнение с индикатором прогресса;
- анонимный и идентифицированный режимы;
- справочники подразделений, проектов, ролей, форматов и направлений;
- шкалы 1–5 и 0–10, текстовые ответы и вариант «Не применимо»;
- условные вопросы по выбранным направлениям;
- защита от технических дублей через idempotency key;
- экран успешной отправки с кнопкой «На главную» для нового прохождения.

### Администрирование

- вход по email и паролю, bcrypt-хеширование и httpOnly JWT-cookie;
- обзор ключевых показателей;
- управление жизненным циклом и версиями опросов;
- просмотр ответов и исключение некорректных ответов из аналитики;
- архив опросов и восстановление;
- управление справочниками;
- журнал действий;
- экспорт отфильтрованных данных в CSV и XLSX.

### Аналитика

- единые фильтры по опросу, подразделению, проекту, формату и анонимности;
- CSAT, NPS, средняя оценка, доля негатива;
- индексы качества результата и сотрудничества;
- динамика показателей и распределение оценок;
- минимальные размеры выборки для защищённого отображения результатов и анонимных комментариев.

## Переменные окружения

Создайте `.env` на основе `.env.example`:

```env
DATABASE_URL="postgresql://user:password@host/database?sslmode=require"
SESSION_SECRET="replace-with-at-least-32-random-characters"
ADMIN_EMAIL="admin@process-office.local"
ADMIN_PASSWORD="replace-with-a-strong-admin-password"
ANALYTICS_MIN_SAMPLE="5"
ANONYMOUS_COMMENT_MIN="3"
```

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения к PostgreSQL. Для Neon используется SSL и рекомендуется pooled connection string. |
| `SESSION_SECRET` | Секрет подписи JWT-сессий, не короче 32 случайных символов. |
| `ADMIN_EMAIL` | Email администратора, создаваемого при первом seed. |
| `ADMIN_PASSWORD` | Сильный пароль администратора. В production обязателен и должен содержать не менее 12 символов. |
| `ANALYTICS_MIN_SAMPLE` | Минимальный размер выборки для отображения агрегированной аналитики. |
| `ANONYMOUS_COMMENT_MIN` | Минимальный размер группы для отображения анонимных комментариев. |
| `SEED_RESET` | Необязательный флаг. Значение `true` разрешает полное удаление и повторное создание демонстрационных данных. |

Файлы `.env` исключены из Git. Не добавляйте пароли, токены и строки подключения в исходный код или README.

## Локальный запуск

Требуются Node.js 20+ и доступная PostgreSQL-база.

```bash
npm install
npm run db:deploy
npm run db:seed
npm run dev
```

После запуска:

- опрос: <http://localhost:3000/s/feedback-2026>;
- админ-панель: <http://localhost:3000/login>;
- health check: <http://localhost:3000/api/health>.

При первом запуске `npm run db:seed` создаёт четыре опроса, справочники, администратора и 56 демонстрационных ответов. Если в базе уже есть пользователь или опрос, повторный seed безопасно пропускается. Используйте `SEED_RESET=true` только когда действительно требуется безвозвратно пересоздать все демонстрационные данные.

## Деплой на Render и Neon

Конфигурация сервиса находится в `render.yaml`:

- runtime: Node;
- тариф: Free;
- build command: `npm ci && npm run db:deploy && npm run db:seed && npm run build`;
- start command: `npm run start`;
- health check: `/api/health`;
- автоматический деплой после изменений в ветке `main`.

В Render должны быть заданы `DATABASE_URL`, `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ANALYTICS_MIN_SAMPLE` и `ANONYMOUS_COMMENT_MIN`. Секретные значения хранятся только в Environment Variables Render. Миграции применяются перед каждой сборкой, а idempotent seed заполняет только пустую базу.

Данные размещены в Neon и сохраняются независимо от остановок или повторных деплоев Render. Для обновления приложения достаточно отправить новый коммит в `main`; Render автоматически соберёт и опубликует новую версию.

## Проверки перед публикацией

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

Текущий набор содержит 10 тестов: расчёт метрик, правила безопасности и интеграционные проверки экспорта.

## Правила расчёта метрик

- CSAT — доля оценок 4–5 по `OVERALL_SATISFACTION`.
- NPS — доля оценок 9–10 минус доля оценок 0–6.
- Индекс качества — среднее индивидуальных средних `EXPECTATIONS_MATCH` и `PRACTICAL_VALUE`, если присутствуют обе оценки.
- Индекс сотрудничества рассчитывается для ответа при наличии минимум трёх применимых оценок.
- Ответы со статусами `INVALIDATED` и `TEST` исключаются из метрик.
- «Не применимо» не считается нулевой оценкой.
- Средние округляются до двух знаков, проценты — до одного, NPS — до целого.

## Ограничения MVP

- нет рассылки приглашений и строгой гарантии «один человек — один ответ»;
- idempotency защищает от повторной технической отправки, но не идентифицирует респондента;
- конструктор ограничен копированием и версионированием готовой структуры;
- отсутствуют rate limiting, отдельная CSRF-защита, SSO и централизованный мониторинг;
- для production-нагрузки рекомендуются резервное копирование, аудит зависимостей, мониторинг ошибок и платный always-on тариф без холодного старта.
